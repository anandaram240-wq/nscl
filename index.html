📐 Standard RSA Template — Memorize This (5 Steps)

RSA 5-Step Formula
Step 1: n = p × q ← Modulus (public) Step 2: φ(n) = (p−1)(q−1) ← Euler's Totient Step 3: Choose e: gcd(e, φ(n)) = 1 ← Public exponent Step 4: d = e⁻¹ mod φ(n) ← Private key (Extended Euclidean) Verify: (e × d) mod φ(n) = 1 Step 5a: C = Mᵉ mod n ← ENCRYPTION Step 5b: M = Cᵈ mod n ← DECRYPTION (verify = original M)

Explain the algorithm for key generation, encryption, and decryption using Rabin cryptosystem with neat diagram.

I. Introduction

The Rabin cryptosystem was introduced by Michael O. Rabin in 1979. It is an asymmetric public-key cryptosystem whose security is provably equivalent to integer factorization — the first cryptosystem to have such a proof.

II. Key Generation Algorithm

StepOperation
Step 1Select two large prime numbers p and q satisfying the Blum integer condition:
p ≡ 3 (mod 4) AND q ≡ 3 (mod 4)
Step 2Compute modulus: n = p × q
Public Keyn (broadcast to all)
Private Key(p, q) (kept secret)

III. Encryption Algorithm (Sender)

Input: Plaintext P where 0 ≤ P < n
Ciphertext C = P² mod n (simple squaring)

IV. Decryption Algorithm — CRT (Receiver)

StepOperation
Step 1Compute roots mod p: a₁ = C^((p+1)/4) mod p and a₂ = p − a₁
Step 2Compute roots mod q: b₁ = C^((q+1)/4) mod q and b₂ = q − b₁
Step 3Find c,d via Extended Euclidean: c·p + d·q = 1
Set Mₚ = d·q mod n, Mq = c·p mod n
Step 44 roots: P1=(a₁Mₚ+b₁Mq)modn, P2=(a₁Mₚ−b₁Mq)modn, P3=n−P2, P4=n−P1
ResultOne of {P1, P2, P3, P4} = original plaintext P

V. Worked Numerical Example (Classroom Notes, Slide 71)

Given: p=7, q=11 (both ≡ 3 mod 4 ✓), Plaintext P=20
ENCRYPTION: n = 7 × 11 = 77 C = 20² mod 77 = 400 mod 77 = 400 − 5×77 = C = 15 DECRYPTION — roots mod p=7: (p+1)/4 = 8/4 = 2 a₁ = 15² mod 7 = 225 mod 7 = 1 a₂ = 7−1 = 6 DECRYPTION — roots mod q=11: (q+1)/4 = 12/4 = 3 b₁ = 15³ mod 11 = 4³ mod 11 = 64 mod 11 = 9 b₂ = 11−9 = 2 EXTENDED EUCLIDEAN (7, 11): 2(11) − 3(7) = 1 ⟹ Mₚ = 2×11 = 22, Mq = −3×7 = −21 ≡ 56 mod 77 4 CRT ROOTS: P1 = (1×22 + 9×56) mod 77 = (22+504) mod 77 = 526 mod 77 = 64 P2 = (1×22 − 9×56) mod 77 = −482 mod 77 = 57 P3 = 77 − 57 = 20 ← ORIGINAL PLAINTEXT ✓ P4 = 77 − 64 = 13
✅ Four Roots: {13, 20, 57, 64} · All verified: r² mod 77 = 15 ✓ · P = 20 recovered!

VI. Disadvantage — 4-to-1 Ambiguity

The primary weakness: decryption always produces 4 candidate plaintexts. Only ONE is the real message. Fix: Sender appends redundant bits (e.g., last 16 bits repeated) before encryption so receiver can identify the correct root.

Concise Answer for 5–6 Mark Questions

Introduction: Rabin (1979) is an asymmetric cryptosystem provably as hard to break as factoring n.

Key Generation: Choose primes p, q both ≡ 3 (mod 4). Compute n=pq. Public Key = n; Private Key = (p,q).

Encryption: C = P² mod n.

Decryption: Compute 4 square roots mod n using CRT: roots mod p using exponent (p+1)/4, roots mod q using (q+1)/4. Combine via CRT to get {P1,P2,P3,P4}. Identify correct plaintext using redundancy.

Disadvantage: 4-to-1 decryption ambiguity. Fixed by padding.

IT Act Structure: 13 Chapters | 94 Sections | 4 Schedules

Provision 1 — Digital Signature & Authentication (Sections 3 & 5)

Section 3: Any subscriber may authenticate an electronic record by affixing a digital signature using an asymmetric cryptosystem and hash function.
Section 5: Where any law requires a document to be signed, a digital signature satisfies such law — legally equivalent to a handwritten ink signature.

Provision 2 — Electronic Governance (Sections 4, 6, 7, 8)

Section 4: Information in electronic form satisfies any statutory requirement of writing or printed form.
Section 6: Filing of forms, issuance of licenses, grants, approvals and payments can be done electronically by government ministries.
Section 7: Electronic retention of records is valid if accessible for future reference in original format.

Provision 3 — Attribution, Acknowledgement & Dispatch (Sections 11, 12, 13)

Section 11 (Attribution): An electronic record is attributed to the originator if sent by: (1) the originator, (2) an authorized agent, or (3) an automated system programmed by originator.
Section 12 (Acknowledgement): Receipt confirmed by any communication/conduct of addressee. If originator stipulates acknowledgement as binding → record is never sent until ack received.
Section 13 (Dispatch): Dispatch occurs when record leaves originator's control.

Provision 4 — Secure Electronic Records (Sections 14, 15)

Section 14: A secure electronic record is verified to have remained unaltered since a specific point in time using an agreed security procedure.
Section 15: A secure digital signature is applied using a private key exclusively under subscriber's control.

Provision 5 — Penalties & Civil Liability (Section 43)

Any person who without permission: accesses computer systems, downloads/copies data, introduces viruses, disrupts network access — is liable to pay compensation up to ₹1 Crore to the affected party.

Provision 6 — Criminal Offences (Sections 65, 66, 67)

Section 11 — Attribution of Electronic Records

An electronic record is attributed to the originator if sent by:

#Condition
1The originator themselves
2A person authorized to act on behalf of the originator (agent/employee)
3An automated information system programmed by or on behalf of the originator

Legal effect: Once attributed, the originator cannot repudiate the record.

Section 12 — Acknowledgement of Receipt

SituationRule
No form of acknowledgement agreedAny communication or conduct of addressee confirming receipt is valid
Originator stipulates binding on ackRecord is treated as NEVER SENT until acknowledgement received
Time specified but ack not receivedOriginator may send notice; if still no ack → treat as never sent

Section 13 — Dispatch & Receipt (bonus for completeness)

Dispatch: Occurs when record enters a computer resource outside originator's control.
Receipt: When record enters addressee's designated computer resource.
Place: Deemed to be principal place of business of originator/addressee.
